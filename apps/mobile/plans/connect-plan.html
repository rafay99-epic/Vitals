Vitals Connect: full vitals, files on every device, a terminal

One Mac, one Android phone, one iPhone, all running Vitals. Each sees everything the Mac measures. Each can browse the others' files and pull or push anything. They share one clipboard history. The phone gets a real terminal on the Mac. All of it runs over your own Wi-Fi or your own Tailscale, encrypted, with no cloud in the middle. Most of the plumbing already exists. This plan adds the missing pieces in six phases, each one a PR into nightly.

3. Architecture

One rule keeps this simple: phones only ever connect out to the Mac. When the Mac (or the other phone) wants a phone's files, the gateway sends the request down the socket the phone already has open, and the phone answers on the same socket. Bytes always move as Drops, so resume, hashing, pinning and progress come for free.

The Mac already measures everything you asked for. Most of it already reaches the phone. The gaps:

Work

  • Contracts (packages/contracts/src/stats.ts): the optional keys above. Free disk and SMART change slowly, so the Mac sends them every 60 s, not every tick.
  • Mac (Remote/RemoteSample.swift): fill the new keys from NetworkStats, DiskStats, DiskHealth, GPUSensor, Battery. SSID needs Location permission on macOS; if it isn't granted, send null and the phone says nothing.
  • Phone: LIVE_TOPICS adds disk. Two new channels in @vitals/ui (disk, and net split from the current tele), both drawn by the existing Trace with a second series. Home shows eight Wave rows; the minis become Power, Swap, Wi-Fi, Free. ChannelDetails gains the blocks in the prototype. The history chart asks for two series where it makes sense (networkIn + networkOut, diskRead + diskWrite, battery + batteryWatts).
  • Alerts: one new guard rule, "Disk is almost full" (under 10 GB or 5%).
  • Tests: contract round trip with and without the new keys; Swift test that free space and capacities are never invented (null when unread); a phone reading test for "--" when a key is missing.

Size: about 2 to 3 days, one PR. Nothing here needs a new phone store build if the native parts stay unchanged (OTA for the JS).

Path safety (test-locked, like the uninstall script)

  • Every path is resolved with realpath and must sit inside a shared root. Symlinks that leave a root are listed as links and can't be followed.
  • Never /System, never the Vitals data folder, never ~/Library unless you share it on purpose.
  • App bundles and packages (.app, .photoslibrary) show as one item; Get zips them.
  • macOS asks once per protected folder ("Vitals would like to access files in your Desktop folder"). The prompt is attributed to Vitals.app because the gateway is its child. If you say no, that place shows "Your Mac said no. Allow it in System Settings › Privacy › Files and Folders."

Phone

  • Files screen: device chips, Places, search, folders, Select, Get, Put files here, file sheet (Get, Look at it, Open on the Mac, Send to the other phone, Share, Trash). Send and transfers stay as shipped.
  • "Look at it" streams images and video from the Drop URL with a short-lived ticket in the query string (players can't send our header), nothing saved.

Size: about 4 to 5 days, one PR. Fake Mac harness gets a fake file tree so the emulator can test it without a Mac.

6. Phase 3: terminal

Mac (gateway)

  • PTY: Bun.spawn([shell, "-l"], { terminal: { cols, rows, data } }), shell from the user's record, cwd home, TERM=xterm-256color, the user's locale. Runs as you; sudo asks for your password like anywhere else.
  • Sessions outlive the phone's connection. Each keeps a 2 MB ring of output and replays it on attach, minus the escape codes that would re-trigger queries (T3 does the same). An idle session ends after 12 hours. A gateway restart ends them all, and the phone says so.
  • Backpressure: at most 64 KB of output in flight per stream until the phone acks, so cat on a big log can't flood the socket or the phone.
  • Saved commands live on the Mac (gateway SQLite), so every device sees one list.

RPCs (scope terminal)

terminal.list                      sessions on this Mac
terminal.open   { cols, rows }     new session, returns id
terminal.attach { id, afterSeq }   stream: replay, then live output chunks (seq, bytes)
terminal.ack    { id, seq }        flow control
terminal.write  { id, data }       keys and paste, max 64 KB
terminal.resize { id, cols, rows }
terminal.close  { id }
terminal.saved / terminal.save / terminal.forget

Phone

  • Full screen, dock hidden. Session chips on top, saved commands and sessions in sheets.
  • Renderer: ghostty-web (Ghostty's parser in WASM, xterm.js API, about 400 KB) in react-native-webview, fed bytes from React Native. Input comes from a React Native text field plus a key row (esc, tab, ctrl latch, arrows, ^C, |, ~, /, paste), so the WebView never handles the keyboard. The web client uses ghostty-web directly.
  • If it isn't smooth enough on a real phone, swap the renderer for a native view. T3 Code ships one (apps/mobile/modules/t3-terminal, libghostty on iOS and Android, MIT, so it can go into this GPL-3.0 app with credit). The RPCs don't change.
  • Unlock with fingerprint or Face ID (expo-local-authentication) on every open after 5 minutes away.
  • The cursor doesn't blink (no repainting animation).

Mac awareness

  • Off until you allow it, per device. First open of a session sends a notification, "Pixel 9 opened a terminal", with End.
  • The menu bar panel lists live sessions with End and End all. Turning the permission off ends that device's sessions at once.
  • The audit log records open, close, device and duration. It never records keystrokes or output.

Size: 5 to 7 days, two PRs (gateway and Mac, then phone and web).

7. Phase 4: phones as file sources

  • Reverse requests: a phone that shares files opens fs.serve, a stream. The gateway pushes requests down it (list, thumb, send) and the phone answers with fs.reply. Bytes go phone to Mac as a normal Drop. No ports open on phones.
  • What a phone shares (Settings › This phone):
    • Android: Photos and videos (MediaStore, READ_MEDIA_IMAGES and READ_MEDIA_VIDEO), Downloads › Vitals, folders you pick with ACTION_OPEN_DOCUMENT_TREE (permission kept across restarts). No "all files" permission: Play only allows it for file managers and backup apps, and it isn't needed.
    • iPhone: Photos (PhotoKit), Files › Vitals, folders you pick (security-scoped bookmarks).
  • Phone to phone: v1 goes through the Mac. Phone A sends to the Mac's staging folder, then the Mac sends to phone B, and the staged copy is deleted when B confirms. A streaming relay (bytes pass straight through) can come later if it matters.
  • When a phone can answer: iPhone only while Vitals is on screen (iOS suspends it otherwise). Android while the app or its transfer service runs. Everything else says "not open", never a fake listing.
  • Mac: a Devices panel to browse phones, with Get and Get all into Downloads › Vitals.

Size: about 5 days, one PR, plus a store build for the new native permissions.

9. Clipboard on every device

This already works hub style: every phone reads the Mac's history and can add to it, so a copy on the Pixel reaches the iPhone through the Mac. Two small additions in Phase 4: each clip records which device it came from ("from Pixel 9"), and "Copy here automatically" can follow clips from the other phone too, not only from the Mac.

  • Encryption: Wi-Fi control traffic is Noise IK (X25519, ChaCha20-Poly1305), Wi-Fi bytes are TLS pinned to the Mac's key, Tailscale is WireGuard plus HTTPS from tailscale serve with the owner-login check. WebDAV listens on loopback only.
  • No cloud: nothing passes through a server we run. Convex stays the website's release proxy only.
  • Small fixes found on the way: the Wi-Fi pair notification says "read and operate" but new devices also get files; there is no rotation for the Mac's Noise key or Drop certificate. Both are worth fixing in Phase 2.

Nobody combines these four. That's the gap.

Where Pro limits would sit (for later)

  • Free: one phone, Wi-Fi, vitals, clipboard, sending files, browsing your Mac.
  • Pro: Tailscale from anywhere, more than one phone and phone to phone, Terminal, phones in Finder and the Mac in Files apps, longer clipboard history.
  • Pricing: with no servers to pay for, a one-time price fits better than a subscription, with paid major upgrades if needed.
  • Check first: Vitals is GPL-3.0. Anyone can build it with the Pro checks removed. What can still be sold: the signed, auto-updating builds, the store apps, and support. The license check would gate the official builds. As the copyright holder you could also dual-license, but every outside contribution makes that harder. Worth deciding before Pro code gets written.

13. Honest limits

  • iPhone can only share its files while Vitals is on screen. iOS gives no way around that.
  • Android can't share the root of Downloads or other apps' private folders to a third-party app; pick subfolders instead.
  • A macOS File Provider (a phone in the Finder sidebar like iCloud) needs a Team ID. WebDAV under Locations is the honest alternative until then.
  • The terminal ends when the gateway restarts (for example on a Vitals update). It says so; it doesn't pretend to resume.
  • Phone to phone through the Mac costs Mac disk space while the file passes through (deleted after delivery).
  • GPU renderer and tiler numbers come from private IOKit keys and may change in a macOS update. They show "--" when missing.
  • Not yet tested: Finder WebDAV speed on folders with thousands of items, ghostty-web keyboard feel on a real phone, Go memory inside an iOS extension.
