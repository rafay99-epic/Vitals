Vitals Remote · apps/mobile + packages/app + packages/ui

Android rebuild plan.

The first screen holds up. Everything past it falls apart: alarm bands eat the home screen, Calm does nothing visible, sheets snap shut, launch blocks on an update check, and the tabs hide what they contain. This plan fixes the causes, not the symptoms, Android first and iOS right after.

Update 2026-10-23, as built: Home follows direction B; every other screen, the floating dock and the flows follow A (see the A + B prototype). Sheets are one custom component on Reanimated + Gesture Handler (one code path for iOS and Android, drag to dismiss, back button, keyboard lift). We did not use react-native-screens formSheet or @gorhom/bottom-sheet: gorhom does not list support for Gesture Handler 3, which this repo uses. The phone app has its own UI kit in apps/mobile/src/ui and reuses only logic from @vitals/app. Tabs are Home, Apps, Control, Alerts, Settings. Updates never block launch.

02 The new philosophy.

Same black, same yellow, orange and red, same Instrument Serif shouting the state. What changes is how the app behaves.

One glance, one line.Home answers "is my Mac OK?" in a single status line. Problems collapse into that line. They never stack.
Plain names, punk skin.Navigation uses words people search for: Processes, Control, Settings. The character lives in type, color, motion and copy, not in riddles.
Tap a thing, get a sheet.Every object (process, alarm, app, emulator, action) opens one native sheet with its actions. One pattern everywhere, so you learn it once.
Tap to undo, hold to destroy.Reversible actions are a tap followed by an Undo toast. Holds are only for Quit, Kill, Restart, Shut down and Unpair.
Never block.No launch gate, no takeover screens. Updates download quietly and apply on the next cold start.
Every action answers.A tap always ends in a visible result: the row changes, the status line changes, or a toast says why it didn't. Silence counts as a bug.

Existing rules still hold: honest readings only, and one shared component per surface (CLAUDE.md rule 5).

Running apps and emulators move from Record into Processes, where you would look for them. "Launch by bundle id" is dropped unless you use it (see open questions). Channel tags (PULSE, PRESS, TEMP) stay on Home as flavor; they label metrics, not navigation.

Sheets become routes

Sheets move out of component state into the root native stack. Android back and predictive back close them, deep links can open them, and the close animation always plays.

04 Decisions, with a pick.

Pick: A, native formSheet

Which bottom sheet?

A · react-native-screens formSheet

  • Already installed (4.30). Zero new deps.
  • Real platform sheet: Material bottom sheet on Android, UISheetPresentationController on iOS. Native open, close and drag.
  • Back and predictive back come free; sheets are routes.
  • Android has had rough edges with keyboard and nested ScrollView.

B · @gorhom/bottom-sheet v5

  • Most control, identical on both platforms.
  • Mature, supports Reanimated 4.
  • JS-driven, one more dependency, and back handling is wired by hand.

C · @expo/ui ModalBottomSheet

  • True Compose sheet.
  • Different API per platform, young, and mixing RN content into it is awkward.

Phase 0 spends one day building the Process sheet with A on a claimed Android emulator: scrolling content, a text field with the keyboard open, two detents, predictive back. If any of those fail, we use B and keep the same Sheet API so screens don't care which one is underneath.

Pick: one status line

How alarms show on Home

One line under the header, ordered by priority: connection lost, then critical, then warning, then a pending order. It reads ▲ Agent crowd · 25 agents · +1 more. Tapping it opens the Alarm sheet with the details, the Calm action and Undo. Nothing else on Home moves when an alarm arrives. Shape and label carry the severity, not just color.

Pick: in-app catalog

Where the design system lives

A Catalog screen, reachable from Diagnostics in the dev variant only, renders every primitive in every state on the real device with real fonts and motion. That is the "design application" you can hold. Storybook for React Native would add a second app and a build pipeline to answer the same question. Before any code, the look gets picked from HTML mocks (Phase 1).

Pick: fix Calm on both ends

What Calm means

  • Mac: once calm is applied, mark the alarm calmed and stop re-raising that rule until calm is undone or the reading changes for real. Dedupe calmActions. Return "nothing to calm" as a neutral outcome, not a failure. Match iOS Simulator processes as emulators. Swift tests cover each case.
  • Phone: a calmed alarm turns from red to dim with "Calmed · 25 agents at low priority · Undo". The tap always ends in a visible change.

06 Design system v2.

This extends packages/ui; nothing is rebuilt from scratch. Colors stay as they are. The additions are roles, spacing, motion and the components that are missing.

LayerTodayv2
ColorRaw palette in theme.ts + theme.css, duplicatedGenerate theme.css from theme.ts (one source). Add roles: surface/0,1,2, accent (yellow), danger, warn, ok.
SpaceLiteral px-[22px] everywhereScale 4 · 8 · 12 · 16 · 22 · 32 as Tailwind tokens. 22 stays the page gutter.
TypeSerif / Sans / Mono + sizesNamed roles: state (serif italic 46), title, row (Geist 15), meta (Mono 11), number (Mono tabular).
MotionDurations onlySprings: press (scale 0.97), enter (existing rise + stagger), tab (bottom-tabs animation:"shift", 180 ms), push (slide_from_right), sheets native. Respect reduced motion. No looping animations: no pulse, shimmer or spinners.
HapticsAd hoc per screenBound to components: select on chip and tab, light on toggle, success on commit, heavy on destructive commit.

07 Phases.

Each phase gets its own branch off nightly and a PR into nightly, tested on a devlease-claimed Android emulator plus your phone through android:dev. Nothing is committed until you say so.

P0Spike · 1–2 days

Measure, confirm causes, settle the sheet choice

  • Baseline screen recordings of every tab on Android, plus cold start time and FPS from Diagnostics.
  • Reproduce Calm on the Mac with log lines (guard.calm.applied) and confirm causes (a) through (d).
  • Build the Process sheet with formSheet. Pass/fail on scroll, keyboard, detents and predictive back.
Gate: short findings note + the sheet pick (A or B).
P1Mocks · 1 day

Pick the look

  • 3 or 4 distinct static directions in an html-brainstorm-grid: Home with the status line, Processes, Control, a sheet. All on true black with the yellow, orange and red set.
  • Each direction shows open and close motion, not just still frames.
Gate: you pick a direction. No component code before this.
P2Foundation · 3 days

Tokens, motion, sheets as routes, non-blocking launch

  • Tokens v2 in ui/theme.ts, with theme.css generated from it.
  • New Sheet on the chosen engine. Root native stack with the sheet routes. Tabs renamed and given transitions.
  • Updates: drop the blocking cold-start check and the resume takeover. Download in the background, apply on the next cold start, and show "Update ready" in Settings.
  • Catalog screen.
ui/theme.ts · ui/motion.ts · ui/feedback/Sheet.tsx · app/App.tsx · app/navigation/types.ts · features/updates/*
P3Home + Alarms · 3 days

Status line, Alarm sheet, Calm that works

  • StatusLine replaces ChartBanners. Pending orders show in the same line with a Cancel in the sheet.
  • Alarms tab: open alarms on top, Calm and Undo next to them, rules moved into a sub-screen.
  • Mac side: calmed state, dedupe, neutral "nothing to calm", Simulator matching, with tests in apps/desktop/Tests.

  • FlashList is only worth adding if FPS drops with 200+ rows; SectionList stays otherwise.

P5Control · 2 days

Tiles that open sheets

  • Power (Sleep, Display off, Lock as taps; Restart, Log out, Shut down through a Confirm sheet), Stay awake, Sound, Hand over (Clipboard, Open link, Locate).
  • Scenes become two tiles. The orders log moves to the bottom.

P6Settings · 1–2 days

Short grouped list, depth through pushes

  • Mac, This device, Connection, Notifications, Updates, Diagnostics, Unpair. Each row pushes a screen or opens a sheet. No mixed content.

P7Polish + iOS · 2–3 days

Edges, accessibility, iOS parity

  • Android: edge-to-edge insets, predictive back on every sheet and push, TalkBack labels, font scale up to 1.3.
  • iOS: run the same flows on a claimed simulator. Sheets are native there already, so this is mostly spacing and haptics.
  • OTA through update:dev to your phone for a 2-day real-use check before the PR.

Total is roughly 16–20 working days. P3 and P4 can run in parallel once P2 lands (P3 owns features/chart and features/alarms, P4 owns features/processes).

09 Open questions.

  1. Tab names. Plain names (Home, Processes, Control, Alarms, Settings), or keep one or two of the medical names for character?
  2. Holds. Are you fine with Lock, Sleep and Display off becoming plain taps with an Undo toast?
  3. "Claim notification". I read this as the in-app alarm bands on Home. If you also meant the Android system notification in the shade, that's a separate fix (channel, style, actions) and gets added to P3.
  4. Launch by bundle id. Do you use it? If not, it gets dropped. If you do, it becomes "Open an app" with a picker of installed apps.
  5. Tablet layout. The wide rail layout is kept but gets less attention. Do you use Vitals Remote on an Android tablet?

10 Out of scope.

  • The macOS app's own UI. The only desktop work is the Calm fix in PressureGuard and RemoteModel.
  • Gateway, pairing protocol and transport (Wi-Fi and Tailscale), beyond what the Calm contract needs.
  • New remote features. This is a rebuild of what exists.
  • The website and marketing app.
