1. Root cause

A 3 second sample of the live process shows 1,065 of 1,669 main-thread samples inside -[NSStatusItem _updateReplicants]. The menu bar icon animation (menuBarAnimated = 1 in your prefs) runs three repeatForever animations inside a status item. macOS re-snapshots status items on the CPU every frame, so the "runs on the compositor, no per-frame CPU" claim in MenuBarController.swift:5-12 and MenuBarHost.swift:4-8 is wrong. The "~11%" figure in the comment is also wrong; it's roughly 60 to 80% here. Sensor syscalls are about 2% of CPU time.

Second-order: .task(id: spinKey) restarts the fan spin every time rpm moves 1%, and a linear(duration: 0) reset doesn't cancel the old repeatForever. Animations likely stack over uptime, which fits the heap growth. Unconfirmed until we heap the Dev build twice an hour apart.

60-second check you can do now: Stable, Settings, Menu bar, turn off "Animate icons". Then top -pid 13568 -stats cpu. It should drop to low single digits.

5. Comments pass (PR 4)

4,041 comment lines vs 20,357 code lines (16.6%). 39 doc blocks run 8+ lines. The same rationale repeats 3 to 4 times (reduceOnBattery, menuBarAnimated, assignIfChanged). ~80 lines narrate history ("the old X", "used to", issue numbers). "Honest" appears in 72 comment lines. Some are wrong: DataHome still describes CSV history, three reference a nonexistent CollapsibleCard, the menu bar ones claim zero CPU.

Keep a comment only if it is:

  1. a safety or privilege invariant (what tests lock, why a path is allowed),
  2. a platform quirk or private-API contract (CF retain rules, IOKit/SMC oddities, AppKit launch order),
  3. a non-obvious perf constraint, said once, where the code is,
  4. a one-line doc where the name isn't enough.

Delete history narration (git has it), philosophy restatements (CLAUDE.md has it), duplicates, and code restatement. Estimate: ~1,100 comment lines go. Worst by ratio: PowerState, CounterRate, Navigator, StartupImpact, DataHome. Worst by volume: AppSettings (175), VitalsModel (174), HistoryDatabase (133).
