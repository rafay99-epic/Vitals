Implementation sequence

  1. Instrument. Record RSS/footprint, active tasks, timers, mounted sections, widget panels, history size, log entries, and scan-result sizes. Profile idle, Overview, widgets, all sections, Liquid Glass, and large scans with Allocations, Leaks, Memory Graph, and VM Tracker.
  2. Reduce UI retention. Mount only the selected section while keeping long-running models alive where scans must survive navigation. Clear or bound completed scan results and test repeated navigation/show-hide cycles.
  3. Make sampling serial. Replace the timeout behavior that can release the sampling gate before a synchronous hardware operation returns. Avoid queued overlap, reduce sampling based on actual visible demand, and coalesce SwiftUI publications.
  4. Repair fan state. Validate plist, helper service, support directory, permissions, and state file. Add a privileged repair path and tests for a missing directory, stale plist, atomic write, helper restart, and manual-to-auto recovery.
  5. Validate OS lanes. Keep macOS 15 as the deployment floor, test the classic fallback there, and test macOS 26+ with the modern SDK and Liquid Glass path. Exercise SMC, IOReport, widgets, sleep/wake, displays, and fan control on both lanes.

Acceptance criteria

Memory

No monotonic resident-memory growth during a 60-minute idle soak. After closing tabs, widgets, and scan results, memory returns close to the post-warmup baseline.

Processing

No overlapping sensor samples after forced delays. Background sampling is limited to metrics actually needed by visible surfaces and enabled alerts.

Fan control

Deleting the support directory produces a clear repair state, and an authorized repair recreates it without requiring a full reinstall.

Safety

All development uses Vitals Dev.app. Stable remains untouched, and each implementation slice is delivered from a branch based on nightly.

Known validation limitation

The local machine has Command Line Tools but not the full Xcode SwiftUI macro plugins, so the baseline swift test attempt cannot complete here. Full Xcode validation is required before treating the branch as build-ready.
